# 云图技能 AI 二次分析效率优化

已在技能源码中落地模型输入精简、一次看图完成两处观察、分组预检和计量。完整五章、指定品牌范围、逐帧覆盖、分析充分性及最终校验保持现有要求。

## 从完整流程定位开销

| 阶段 | 当前职责与发现 | 本次处理 |
|---|---|---|
| pre_input → RPA | 三批列表、详情、CSV 落盘与恢复；秒级素材数和榜单品牌范围是不同参数 | 保持参数及采集语义，直接复用已有批次验证 |
| 规范化 → 五包 | 已计算指标聚合、环比、行业比较、人群、营销标签、关键词和曲线 | 保留完整事实及其哈希；不要求模型重新统计 |
| 五包 → 模型 | 原入口要求全文读五包、统一 Schema，再读 task；第一章重复传输逐素材列表，第二章重复品牌素材，单素材 task 仍指向整包 | begin-analysis 为每份 task 提供 scopedFacts + outputSchema + readingRule，原 factInput 仅供必要溯源 |
| 模型写作与看图 | 第四、五章都要观察同批帧；原流程没有明确同次完成；每份草稿启动一次检查 | 按素材看原图，同次填写两章观察；全部理解完成后做整批分类；每组草稿一次检查 |
| 组装 → attest → 报告 | 组装器自身已经完整检查，入口却要求紧邻组装前再全量检查 | 直接调用组装器执行完整检查；保留 attest、快照、无损组装、HTML/Excel/ZIP 校验 |

代码中没有独立模型 API 调用服务。`single_model_call` 是历史契约标识，不能从它推断实际调用次数或模型耗时。本次减少确定性输入与编排开销，未更换模型。

## 具体改变

1. **第一章只读取聚合所需事实。** current、previousPeriod、industryBenchmark 及品牌 current 的 materials 改为完整 materialIds。保留样本量、四项指标、日期、可用性和全部比较值；完整 hotMaterialFacts 原样保留。省去的普通逐素材明细仍在正式五包内，第一章原本就禁止逐条个案分析。
2. **第二章无损去重。** 将各范围重复的 topMaterials 存到 materialsById，每个 scope 的 topMaterialIds 保留原顺序，可还原全部素材对象。人群桶、营销类别、长尾标签、空品牌全部保留。同 ID 的事实若冲突，保留完整原结构。
3. **第三、五章按范围供给。** 品牌脚本 task 只带本品牌事实；全量脚本 task 不重复各品牌包。单素材 task 保留自身完整脚本、公式、脚本引用和帧清单，省去不参与模型分析的秒级曲线；曲线继续由报告展示。
4. **一次看图完成两处观察。** 按素材查看每张成功 JPEG，同次完成第四章 frameUnderstanding 和第五章 frame_observations，及时保存。全部理解完成后才做整批分类及品牌洞察。证据模糊时仍可重看；不把另一章的业务结论当作证据。
5. **分组检查、局部修复。** `--part` 支持重复，保留单份检查。示例 19 份草稿可分为榜单/人群、脚本/品牌、两组单素材、整批视觉共 5 组；每次仍验证完整事实和资产，没有跨命令跳过校验的缓存。未知 part 报错，组内错误集中返回。
6. **可核验输入和开销。** 新 task 文件保存哈希，恢复和检查时验证；旧 workspace 仍可原样恢复。workspace.inputMetrics 记录五包、投影及 task 字节量；validation.timingsSeconds 记录输入验证和草稿检查耗时。组装内部检查也保留这些计量。

## 真实批次测量

样本：`yuntu-rankings-analysis-20260903-20260910-exposure-top1000-wonderlab-wgb-yzy-xc-fiboo`，5 个指定品牌、10 个素材、51 张成功帧、19 份草稿。使用原 manifest 绑定事实和历史模型正文进行离线回放，没有重新采集或生成新的业务结论。

| 章节 | 原章节文件字节 | 新任务中的事实字节合计 |
|---|---:|---:|
| 01 榜单 | 2,826,223 | 162,026 |
| 02 人群与营销 | 1,350,948 | 990,672 |
| 03 全量与品牌脚本 | 83,886 | 74,573 |
| 04 视觉 | 24,145 | 24,059 |
| 05 单素材 | 82,165 | 24,231 |
| **合计** | **4,367,367** | **1,275,561** |

包含各部分 Schema、引用约束等开销后，全部 task 文件共 **1,385,831 字节**。相比原五包 4,367,367 字节，默认文件读取体积减少 **68.3%**。这个比较没有把旧流程额外读取统一 Schema、旧 task 或重复原包的开销算入基线，也不是 token 测量。

同一套历史草稿的本地 CLI 顺序预检，逐份 19 次合计 **6.31 秒**，分组 5 次合计 **2.40 秒**。这是一次本机测量，含进程启动、输入哈希和语义检查；两种方式都检查全部草稿。它不包含模型思考、输出生成、工具往返网络和修复重试。

**不能据此声称完整 AI 分析提速 68.3%。** 本轮验证的是输入负担与本地校验开销。下一次新分析才可从执行日志测量事实准备、文本写作、看图、返工和交付的真实墙钟时间。现有业务正文的生成量仍受五章、品牌独立分析和充分性要求影响，本次未降低这些要求。
