## 3. `03｜脚本洞察`：无数据占位

### 3.1 目标与边界

第 03 部分先作为正式报告区块和导航锚点交付，使报告结构稳定；它不读取、汇总或展示虚构脚本内容。当前云图 RPA 尚未稳定提供脚本文本、内容公式和带时间戳段落，因此区块应显示一个明确的数据可用性状态。

本轮不做：

- 不依据标题、卖点标签、点击峰或画面生成代表话术。
- 不从模型输出中接受无原始脚本文本支持的脚本结论。
- 不展示“即将支持”或产品功能说明。
- 不把 `data_availability` 中偶发或不可验证的字段，当作可汇总的脚本数据。

### 3.2 报告呈现

HTML 与 Markdown 都新增 `03｜脚本洞察`。正文固定表达当前数据状态：

```text
本次云图 RPA 未提供可用于汇总的脚本正文与时间戳段落；本部分暂不输出话术、内容公式或帧-话术对应关系。
```

区块必须包含一个数据状态标签：`脚本数据：未接入`。它是数据限制说明，不是模型结论；不需要 `evidence`，也不触发当前 AI 分析 JSON 的新增必填字段。

### 3.3 未来启用门槛

第 03 部分仅在以下条件同时满足后，才从占位升级为数据看板：

1. 连接器参考页和真实样例确认 `script_text`、`content_formula`、`script_segments` 的来源字段及空值语义。
2. 每条可用段落有确定的起止秒或毫秒，且与视频时间轴同一口径。
3. 规范化、事实包、模型输出和报告校验均能传递同一个 `data_availability` 状态。
4. 测试覆盖脚本缺失、空文本、非法段落、没有时间戳和完整段落五种状态。

在此之前，任何第 04 部分中的高光帧都不得宣称对应某句脚本话术。

## 4. `04｜高光画面洞察`：数据与截帧标准

### 4.1 输入与运行时机

对每个已成功获取详情的入选素材，在 `prepare-analysis` 阶段自动生成标准高光帧。标准报告不再依赖用户传入多指标选择；“点击指数”是唯一参与峰值选择的趋势。

输入：

- `normalized/detail-records/<material_id>.json` 中的 `video_url`。
- 同一详情记录中趋势名称为 `点击指数` 的完整时间序列。
- 当前批次选中的素材 ID、标题、排名和核心指标。

输出：

- `highlights/<material_id>/` 中的 JPEG 文件。
- `highlights-manifest.json` 中每个期望帧的处理结果。
- `yuntu-analysis-data.json` 的 `materialFacts[*].highlightFrames` 和 `highlightFrameAvailability`。

视频下载、FFmpeg 不可用或单帧截取失败不阻断事实包；每个失败帧都必须保留具体失败状态，报告只能展示成功 JPEG。

### 4.2 选帧算法

标准与千川技能保持一致：

```text
selectedFrames = [封面帧 0s] + sort(点击指数的全部局部峰值, 点击值 DESC, 秒数 ASC)[:5]
```

具体规则：

1. **封面帧**：固定截取 `0s`，标记 `frame_type = cover`，不参与峰值排序。
2. **点击峰值帧**：只从 `点击指数` 序列找局部峰值，标记 `frame_type = click_peak`，以点击值降序、秒数升序取最多 5 个。
3. **平台值**：连续相等的平台只保留最早秒数，避免同一视觉片段重复截帧。
4. **边界点**：首点或末点严格高于唯一相邻点时可作为局部峰值。
5. **不足 5 峰**：保留实际峰值数量，不补造、不以高点区间或其他指标替代。
6. **同秒去重**：同一秒只生成一张 JPEG；本标准只有一个峰值指标，理论上不会产生跨指标重复，但清单仍以秒数为唯一键。
7. **命名与证据**：每帧记录 `material_id`、`second`、`frame_type`、`peak_rank`、点击值、相对文件路径、成功/失败状态与稳定 `frame_ref`。

建议的事实记录：

```json
{
  "frame_ref": "highlight:123456:click_peak:12",
  "material_id": "123456",
  "second": 12,
  "frame_type": "click_peak",
  "peak_rank": 2,
  "click_value": 87.3,
  "available": true,
  "relative_path": "highlights/123456/03-012s.jpg"
}
```

普通封面帧的 `peak_rank` 和 `click_value` 为 `null`；若 `0s` 同时是点击指数峰值，则封面帧保留对应的 `peak_rank`、`click_value` 和双重原因，但不额外生成重复图片。不得将云图的“点击指数”改写为真实点击次数，也不得将峰值解读为转化因果。

### 4.3 高光视觉洞察数据契约

在现有模型分析 JSON 中增加 `highlightDashboard`，仅消费事实包内成功 JPEG。模型必须实际查看每张 `relative_path` 对应的图片后再生成该对象。

```json
{
  "highlightDashboard": {
    "availability": {"available": true, "reason": ""},
    "groups": [
      {
        "category": "portrait",
        "frame_refs": ["highlight:123456:click_peak:12"],
        "common_patterns": ["..."],
        "derivative_directions": [
          {"title": "...", "body": "...", "frame_refs": ["highlight:123456:click_peak:12"]}
        ]
      }
    ]
  }
}
```

约束：

- 分类固定顺序为 `portrait`（人像）、`product`（产品）、`other`（其他）。
- 每张成功 JPEG 必须且只能出现在一个分类的 `frame_refs` 中；失败帧不得被分类。
- 分类为空时不输出空的共同洞察或裂变方向；无成功帧时 `groups` 为空，并在报告显示不可用原因。
- `common_patterns` 和 `derivative_directions` 只描述可从所引帧观察的构图、景别、主体、场景、镜头表现或可复用画面方向。
- 方向必须引用本分类中的 `frame_refs`，不得引用其他分类或没有成功落盘的帧。
- 禁止声称某张帧对应具体话术、用户动作、投放效果提升或转化因果。

### 4.4 报告结构

第 04 部分借鉴千川的“分类帧库 + 共性洞察 + 大图预览”结构，但保持云图报告的现有视觉系统：

```text
04｜高光画面洞察
  数据口径：每条素材 = 0s 封面 + 点击指数局部峰值 Top5
  人像画面
    共性洞察
    裂变方向
    帧库（图片、素材标题/排名、帧类型、秒数、点击指数）
  产品画面
    共性洞察
    裂变方向
    帧库
  其他画面
    帧库
```

帧卡片应提供：

- 缩略图和可键盘操作的大图预览，`Escape` 关闭。
- 素材排名、标题、`material_id`、封面/点击 TopN 标签、秒数与点击指数。
- 图片加载失败时不输出损坏图片；素材与该分类的其他成功帧仍可阅读。
- 没有成功帧时显示“暂无可用高光帧”，并展示来自事实包的失败原因，不将其写成视觉结论。

03、04 的导航锚点必须与正文一一对应，移动端沿用现有横向可滚动目录。用户可见正文不展示原始 `evidence` JSON；完整帧记录和分类引用保留在 `final-report-data.json`。

## 9. `05｜单素材深度分析` 设计

### 9.1 目标与边界

第 05 部分服务于从“行业共性”下钻到“某一条素材为何值得观察”的阅读路径。它复用第 04 部分已经产生的高光帧事实和详情中的秒级趋势，不重新下载视频、不重新选帧，也不以模型补造脚本、话术或转化解释。

每个入选素材提供一个可切换的深度分析面板，包含：

1. 素材身份与榜单表现摘要：排名、标题、`material_id` 和已有的核心列表指标；只展示事实包中存在的值。
2. 六帧高光展示：第 `0s` 封面帧与点击指数局部峰值 Top5，最多 6 张。
3. 高光帧观察：模型实际查看每一张成功 JPEG 后，对画面主体、景别、构图、产品露出、人物状态或场景作可回看的描述。
4. 秒级拆解：以云图现有的五条“指数”趋势替代千川的“互动时序分析”。

本节不展示脚本文本、内容公式、脚本标签、帧-话术关系、真实点击/点赞/评论次数、转化提升或因果结论。第 05 部分是素材级的观察与时序事实看板，不是完整视频理解或归因工具。

### 9.2 与千川设计的取舍

| 千川单素材能力 | 云图第 05 部分处理 | 原因 |
|---|---|---|
| 封面 + 点击峰值帧 | 原样复用，固定为最多 6 帧 | 两个技能的高光选帧口径已对齐 |
| 帧级视觉观察 | 原样复用，但只允许描述画面可见信息 | 云图当前可以提供 JPEG，不能提供可靠脚本证据 |
| 互动时序分析 | 改名为“秒级拆解” | 与云图界面的用户语言一致 |
| 点击、流失、点赞、评论、转发、新增粉丝等计数 | 使用云图实际提供的五个“指数”趋势 | 数据口径不同，不能把指数写成次数 |
| 脚本分析、脚本公式、帧-话术对应 | 明确不进入本轮 | RPA 尚未提供可汇总的可信脚本字段 |

云图的五个固定秒级指标为：`点赞指数`、`流失指数`、`点击指数`、`互动指数`、`评论指数`。它们的名称、数值和秒数均直接来自 `trend_series`；其中“流失指数”仅表达曲线数值，不把峰值默认描述为正向或负向表现。

### 9.3 报告结构与交互

报告主目录新增 `05｜单素材深度分析`，锚点为 `#material-deep-dive`。正文使用可键盘操作的素材页签，默认打开榜单排名最高的入选素材；页签只切换一个面板，避免将多条素材的高光帧和秒级曲线混在同一屏。

```text
05｜单素材深度分析
  [#1 素材标题] [#2 素材标题] ...
  素材身份与表现摘要
  高光帧序列（最多 6 张，按秒数升序）
    0s 封面帧 / 点击 TopN 峰值帧 / 大图预览
  高光帧观察
    每张成功帧的可见画面观察
    基于已观察帧的素材级总结
  秒级拆解
    点赞指数 / 流失指数 / 点击指数 / 互动指数 / 评论指数
    各指标曲线、高点区间、流失区间与数据可用性状态
```

六帧的排序规则与展示规则：

1. 封面帧固定为 `0s`，优先展示。
2. 点击峰值帧在画廊中按秒数升序展示，以保留视频时间线；卡片同时展示其“点击 TopN”排名和点击指数值。
3. `0s` 同时命中点击峰值时，页面只展示一张图片，在事实中保留“封面 + 点击峰值”的双重原因，不能显示两张重复卡片。
4. 视频下载、截图或单帧失败时，不渲染损坏图片；显示实际成功帧数和失败原因，不用其他秒数或其他趋势补位。
5. 每张帧卡片沿用第 04 部分的大图预览、键盘焦点和 Escape 关闭行为。

高光帧观察采用“帧级观察 + 素材级归纳”两层：帧级观察必须引用该帧的 `frame_ref`；素材级归纳只总结被引用的成功帧共有或可对比的画面特征。不得从画面观察推出某秒对应话术、用户行为、实际互动次数或业务结果。

### 9.4 秒级拆解的数据契约

`prepare-analysis` 为每个 `materialFacts[*]` 新增 `secondLevelBreakdown`，保持趋势数据与渲染数据同源。该对象始终按固定五指标顺序输出，即使某指标不可用也保留状态，避免 UI 根据返回顺序猜测指标含义。

```json
{
  "metrics": [
    {
      "trend_name": "点赞指数",
      "available": true,
      "missing_reason": "",
      "points": [{"second": 0, "value": 0.2}],
      "high_points": [{"start_sec": 3, "end_sec": 5}],
      "loss_points": [{"start_sec": 6, "end_sec": 7, "loss_percent": 0.18}]
    }
  ]
}
```

规则如下：

- `points` 仅来自同一素材、同一 `trend_name` 的 `trend_series[*].series`，按秒数升序去重；冲突重复秒数是数据异常，不能任取其一。
- `high_points` 和 `loss_points` 仅保留同一指标的云图原始区间；`loss_percent` 缺失时保留为空，不从曲线反推。
- 曲线仅展示指数相对变化和云图返回的区间标记，不转换为真实点击、互动或评论量，也不跨指标归一化比较绝对大小。
- 单一指标无有效点时显示“该指标暂无可用秒级数据”及 `missing_reason`；有曲线但没有高点或流失区间时，仍可正常展示曲线。
- 图表将五个指标以独立小图纵向展示，桌面两列、移动端单列；不使用同一纵轴叠加五条不同口径指数，避免视觉上暗示可直接比较。

### 9.5 模型分析与校验契约

模型输出新增 `materialDeepDives`，每一个入选素材恰有一项。脚本字段不进入该对象。

```json
{
  "materialDeepDives": [
    {
      "material_id": "123456",
      "frame_observations": [
        {"frame_ref": "highlight:123456:cover:0", "observation": "..."}
      ],
      "visual_summary": "...",
      "second_level_observations": [
        {"trend_name": "点击指数", "summary": "...", "evidence_seconds": [3, 8]}
      ]
    }
  ]
}
```

渲染前校验：

1. `materialDeepDives` 与入选素材一一对应，不能漏素材、重复素材或引用未入选素材。
2. 每张成功高光 JPEG 在其所属素材的 `frame_observations` 中恰好出现一次；失败帧不得被观察。
3. `frame_ref` 必须属于当前 `material_id`，不可跨素材引用。
4. `second_level_observations[*].trend_name` 只能取五个固定指标；`evidence_seconds` 必须存在于同指标的 `points` 中。
5. 无可用高光帧或无可用秒级指标时，输出可用性说明，不要求模型编造观察。
6. 对用户可见文本执行现有的反因果、反脚本推断与健康功效限制；新增拦截“真实点击次数”“真实互动次数”“转化由某帧导致”等错误表述。

### 9.6 实施路径与验收

| 阶段 | 实现落点 | 验收结果 |
|---|---|---|
| M4.1 事实包 | `yuntu_analysis.py` 从已规范化详情生成五指标 `secondLevelBreakdown`；高光帧去重并保留双重入选原因 | 每个入选素材都有固定顺序的五指标状态和最多六张不重复帧 |

### 9.7 本阶段非目标

- 不接入或推断脚本文本、内容公式、脚本段落与帧-话术关系。
- 不播放、下载或打包完整视频；报告只引用已生成的本地高光 JPEG。
- 不把五个指数换算成互动次数，不与千川的计数型指标直接比较。
- 不以高光帧或秒级曲线生成转化归因、投放效果承诺或健康功效表述。
