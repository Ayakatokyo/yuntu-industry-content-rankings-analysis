## 四、根因分析

### 1. 参数格式没有在执行前做本地确认

品牌筛选参数并不是多个独立参数，而是一个逗号分隔字符串，并且必须搭配：

```bash
--brand-scope-type SPECIFIED_BRANDS
```

这类参数约束应该在真实 RPA 调用前确认，而不是通过失败重试发现。

### 2. 输出目录复用机制存在误用风险

技能为了支持中断续跑，会复用已落盘的列表文件。这是正常能力，但在业务筛选条件变化时会变成风险。

只要以下任一条件变化，就不能复用旧目录：

- 账号
- 行业
- 时间范围
- 品牌范围
- 指定品牌
- 年龄筛选
- 性别筛选
- 八大人群筛选
- 榜单限制
- `targetTopN`
- `candidateTopN`

本次第一批问题的核心就是：业务条件变化后仍使用了历史共享目录。

### 3. 状态判断缺少交叉验证

manifest 是重要状态文件，但不是运行中唯一真源。

在进程运行中，manifest 可能尚未完成写回，但列表、详情请求参数或详情文件已经落盘。因此不能只根据 manifest 的 `running` 和空数组判断流程阶段。
