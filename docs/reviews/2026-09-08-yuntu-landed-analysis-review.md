## 事实包、提示词、门禁分别有什么问题

1. **事实包：曾把“有数据”错误表达为“无数据”。** 新结构的 Python repr、别名及五类趋势映射需要在数据处理层统一解决。现行 HEAD 已含 `fabf4ca`，本轮未重复修改解析器；运行现有解析/规范化/事实包回归确认通过。不能仅因上游有字段就认为脚本正文可用，也不能仅信一个错误 availability 标记。
2. **提示词和执行规则：重分析路径不清楚，输出负担大。** 原入口只有采集主流程，分析要求“同一次模型调用”，没有明确中间草稿恢复方式；容易在多包、几十张帧、多个分类投影和长 JSON 之间长时间停留。第一章要求 420–700 字、第二章要求 240–420 字，同时要求缺失时“数据不足”，也会诱发为满足结构而套用泛化结论。没有对照实验能证明这是某次中断的唯一原因，但规则存在可直接改善的冲突。
3. **门禁：一处误判和一处正确拒绝必须分开。** 原表达是“仅少量素材返回了可用的内容公式或标签结构，覆盖不足以支持行业普遍结论”。正则 `行业(?:普遍|规律)` 不看否定语境，误判成外推。67 帧只分类 12 帧则确实不完整，不能放行。40 字逐帧提示与运行时 24 字下限也不完全一致，但没有发现这批失败由该长度差直接触发，因此本轮不任意降低阈值。
4. **执行闭环：一次失败后没有明确的局部恢复方法。** attest 拒绝后应修复对应模型输出并继续渲染；“程序化兜底禁止”应限制模板生成业务结论，而不是禁止把模型已写的章节无损组装成 JSON。反过来，存在临时生成脚本也不自动证明其中洞察来自充分看图，单凭 provenance 的 generator 名称无法验证这一点。
