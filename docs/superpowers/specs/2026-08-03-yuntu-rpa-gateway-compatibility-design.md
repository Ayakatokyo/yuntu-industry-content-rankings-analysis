# 云图 RPA 网关兼容性设计

## 背景

真实平台运行记录表明，`ENV_BACKEND_HOST` 在子进程中会被平台改写为可用的 `http` IP 网关；原技能仅允许 HTTPS 域名且拒绝任何基路径，导致连接器在发起请求前退出。直接使用 `.env` 中的 HTTPS 域名又会漏掉实际所需的 `/api` 前缀并返回 404。另一次实际请求以网关 504 结束，耗时约 600 秒。

已跑通的千川技能将 `ENV_BACKEND_HOST` 作为平台受信任的网关基地址：保留其协议、主机和路径，仅去除结尾斜杠后拼接固定 API 路径。本设计将云图对齐该契约，不复制千川的业务连接器或视频处理流程。

## 目标与非目标

目标：

- 兼容平台注入的 HTTP/IP 网关和带 `/api` 的网关基路径。
- 保持固定云图连接器元数据、凭证仅来自环境变量和输出路径安全约束。
- 将网关失败记录为可行动的诊断信息，避免误报为业务参数或素材数据问题。
- 用离线回归测试固定运行时契约。

非目标：

- 不改变连接器 `function_code`、`platform`、`data_source_type` 或业务筛选参数。
- 不重试或并发化列表请求；504 的服务端根因不由客户端掩盖。
- 不将千川的隔离进程、视频下载或预检框架迁入云图技能。

## 运行时网关契约

`runtime_config` 将 `ENV_BACKEND_HOST` 视为平台注入的受信任基地址，执行以下最小校验：

- 三个必需环境变量均为非空字符串。
- 网关地址可解析，具有 `http` 或 `https` 协议和主机。
- 拒绝 userinfo、查询参数和片段。
- 保留合法路径，包括空路径、`/api` 和未来的平台前缀；标准化为无末尾 `/` 的基地址。

随后以 `base + "/adg/v1/..."` 构造请求。HTTP/IP 不再视为客户端校验失败，因为平台实际以该形式注入并已验证账户查询可用。

## 失败语义与输出

`list-accounts`、列表 fetch 和详情 fetch 均沿用固定端点和既有 HTTP 状态校验。错误信息将包含操作阶段、HTTP 状态（在可获得时）和已脱敏的网关诊断分类；不得回显授权值、会话 ID 或文件临时 URL。

列表请求失败继续写出 `batch-manifest.json` 并以非零状态退出，且不启动详情请求。对 504，清单错误须明确这是网关超时，提示检查服务端任务或缩小筛选范围；不把它归因于素材不存在。请求超时维持现有配置，本次不以未经验证的更短客户端超时替代网关上限。

## 技能指引

SKILL.md 将明确：运行前只检查所需变量是否存在；优先使用平台运行时注入的 `ENV_BACKEND_HOST`，不得用 `.env` 中看似更安全的值覆盖它。调用 `list-accounts` 作为连通性检查；该请求成功后再执行 fetch。出现 404 时检查基路径；出现 504 时保留 manifest 并报告网关超时。

## 测试

- HTTP/IP 基地址可用于账户查询和列表调用。
- HTTPS 域名带 `/api` 前缀时，端点拼接正确。
- 空值、无协议、userinfo、查询参数和片段在不发请求前被拒绝。
- 504 在列表批次中写入 `list_failed` manifest，且错误信息保持脱敏。
- 既有固定连接器元数据、参数校验、批处理和技能契约测试继续通过。

## 验收标准

在与日志一致的 `http://IP` 运行时网关下，`list-accounts` 不再被本地 URL 校验阻断，并使用正确的 `/adg/v1/agent/rpa/authorizations/query` 端点。带 `/api` 的网关地址也能正确拼接调用路径。网关返回 504 时，任务在现有批次清单中以可诊断的 `list_failed` 状态结束。
