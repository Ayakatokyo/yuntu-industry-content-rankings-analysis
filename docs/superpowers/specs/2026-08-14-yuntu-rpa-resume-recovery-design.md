# 云图 RPA 中断续跑设计

## 目标

在不修改生意高手执行器、不引入并发或网关回调的前提下，使云图榜单技能能从同一运行契约下的中断批次恢复，并避免重复请求已持久化的详情数据。

## 范围

- `SKILL.md` 将 `fetch` 明确为长任务，要求异步执行并在中断后先运行 `status`。
- `fetch_batch` 复用旧 manifest，并从已存在的规范化详情记录恢复成功项。
- 已提交但没有详情落盘的素材标记为 `unresolved_after_interruption`；默认续跑不重新提交它们。
- 新增 `retry-unresolved` 命令，仅在用户明确要求时重试这类素材。
- 默认候选池从目标数的三倍收缩为 `targetTopN + 2`。

## 非目标

- 不修改平台外层任务超时、RPA 网关或回调协议。
- 不改为并发请求，不假设网关的并发限制或幂等语义。
- 不尝试恢复已被终止进程错过的 HTTP 响应；网关未提供查询接口时，该结果只能显式重试。

## 数据流

`fetch` 发现同一契约的批次时，先加载旧 manifest，再扫描 `normalized/detail-records/`。存在且可验证的详情以候选中的 rank 和分组信息恢复到 `selectedMaterials`；这些 ID 不再调用 RPA。旧 manifest 中已提交但未成为成功、失败或取消记录的项目写入 `unresolvedMaterials`。常规续跑跳过未确认项目并继续后续候选；`retry-unresolved` 才会重新调用这些项目。

## 验收条件

1. 详情文件已存在时，续跑不会再次调用该素材的详情连接器。
2. 中断时已提交但未落盘的素材不会被常规续跑静默重试。
3. `retry-unresolved` 显式重试未确认素材并将成功结果写回 manifest。
4. 全量单元测试与技能契约测试通过。
