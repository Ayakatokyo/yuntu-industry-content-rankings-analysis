# 第四部分本批次标准细分类与分布图设计方案

## 目标

在现有“标准分类 / 本批次标准”双模式基础上，提升本批次标准的区分度：模型根据同批次高光帧的逐帧理解结果，按视觉角色、信息机制和构图动作进行更细粒度的分类；在每个品牌 Tab 的“本批次标准”面板中新增分类分布柱状图，直观看到各动态类别包含的高光帧数量与占比。

## 范围与非目标

本次只影响第四部分：

- 修改高光分类提示词及其 Schema/确定性校验，要求有证据时拆分更多语义明确的类别；
- 在 Presentation 中确定性计算每个品牌范围的批次分类分布；
- 在“本批次标准”Tab 面板内渲染与八大人群柱状图风格一致的竖向柱状图；
- 保留“标准分类”及现有本批次分类卡片、共性洞察、裂变方向和图片交互。

不改变标准分类规则，不修改第一、二、三、五部分，不重新采集高光帧、不重新生成图片理解以外的 RPA 数据，也不让模型直接输出最终占比。

## 本批次分类规则

提示词继续要求先逐帧理解、再整批归类。新的粒度策略如下：

- 类别必须对应可观察且可复用的视觉角色或信息机制，例如“产品包装与成分信息”“人物使用动作”“结果状态展示”，不得使用“其他 1/其他 2”等无语义占位名；
- 对成功帧数量 `n`，在证据允许时按以下目标拆分：`n≤3` 目标 2–3 类，`4≤n≤7` 目标 3–6 类，`n≥8` 目标 6–10 类；类别数不得超过成功帧数；
- 同一类别内的帧必须共享明确的主体/动作/信息机制，若仅因颜色、秒数或品牌不同不得拆类；若视觉机制明显不同，即使只有一张帧也可以保留独立类别；
- 每帧必须且只能归入一个批次类别。无法支持目标数量时，按证据最大化原则输出较少类别，不得拆出重复或空泛类别；若无法形成至少两个有意义类别则将批次分类置为不可用；
- 每个类别继续输出与标准分类一致的 `3 条共性洞察 + 3 条裂变方向`，并保持帧引用只指向本组。

提示词只约束分类的语义粒度和证据边界，不写死具体类别名称。这样不同批次可以产生不同但可解释的分类规则。

## 数据契约与确定性分布

`batchClassification.groups` 继续是唯一分类事实源。Presentation 在已有品牌范围投影完成后，对每个 `classificationModes[id="batch"].categories` 计算：

```json
{
  "distribution": {
    "totalFrames": 24,
    "buckets": [
      {"category": "product-packaging", "label": "产品包装与信息", "count": 6, "share": 0.25}
    ]
  }
}
```

`count` 为该品牌范围内成功高光帧数，`share = count / totalFrames`。分类投影完成后再计算分布，避免全品牌分母误用于单品牌 Tab；分布桶按模型返回的批次分类顺序保持稳定。`totalFrames` 为 0 或批次分类不可用时不生成桶，并保留不可用状态及原因。

该分布是确定性事实，不接受模型直接提供的 count/share；渲染前校验桶计数总和等于 `totalFrames`、每个类别仅出现一次、share 在 0–1 范围且总和接近 1。

## 前端呈现

每个支持分类切换的品牌 Tab，在“本批次标准”面板顶部、分类 Tab 之前插入一个 `本批次标准分类分布` 图表卡片：

- 使用与八大人群分布相同的纵向柱、网格线、棕金色系和 tooltip 视觉语言；
- 横轴显示动态分类名称，柱高表示该品牌范围内的高光帧数量占比；柱顶/tooltip 同时显示 `N 帧` 与 `X%`，并显示总样本数；
- 保持批次分类原始顺序；类别较多时允许横向滚动，不能压缩到无法阅读；
- `aria-label` 明确“本批次标准分类分布柱状图”，每个柱子包含可读的类别、帧数和占比；
- 图表只出现在“本批次标准”模式，不出现在标准分类模式或非高光章节；批次标准不可用时显示现有不可用提示，不渲染空图表。

图表与卡片分类 Tab 联动但不改变分类选择：切换类别 Tab 只改变下方洞察与图片，分布图保持作为该品牌批次全貌的总览。

## 错误与兼容性

- 历史分析 JSON 没有新粒度元数据时，仍可按现有 `groups` 读取；Presentation 依据已有帧引用计算分布。
- 动态分类不可用、分组为空或覆盖不完整时，保留标准分类可用状态；批次面板继续显示不可用原因，不伪造分布。
- 类别重复、帧重复/遗漏、分布计数不一致时，报告校验失败并指出批次分类错误；不静默修正模型结果。
- 分布图失败不影响标准分类、批次分类卡片和其他章节的渲染；只有数据契约错误才阻止报告生成。

## 验收标准

- 提示词明确要求在证据允许时使用 2–3 / 3–6 / 6–10 的细分类目标，禁止无语义占位类别，并保留每组 3+3 洞察约束。
- Schema/校验拒绝超过成功帧数、重复、空泛或无法唯一覆盖成功帧的批次分类。
- 每个品牌批次模式拥有确定性 `distribution.totalFrames` 和按动态分类顺序排列的 buckets；桶计数与分类帧数一致。
- “本批次标准”面板显示可读的竖向柱状图、类别标签、帧数、占比和可访问文本；标准分类面板不显示该图。
- 现有双分类切换、卡片分页、图片预览、Excel 导出和其他章节回归测试通过。
