# 第四部分高光帧按需 Excel 导出与双分类图片墙设计方案

## 目标

第四部分的 Excel 导出不再作为 `final-report` 的预生成产物。报告目录及其同级 ZIP 仅保留 HTML、Markdown、JSON 与报告图片资产，避免一份内嵌图片的工作簿重复占用报告数据包空间。

用户仍可针对同一份报告按需生成 Excel。导出的工作簿保留明细资产 Sheet，并将原“高光帧图片墙”升级为两张同级图片墙：`标准分类` 与 `本批次标准`。二者均按“品牌 → 画面分类”两级组织图片。

## 范围与非目标

本次仅调整第四部分的 Excel 导出链路与工作簿内容：

- `final-report/` 和 `final-report.zip` 不含 `highlight-frames.xlsx`；
- 新增独立 CLI 导出入口，使用已有报告事实包、Presentation 和本地高光帧资源生成工作簿；
- `高光帧资产` 明细 Sheet 保持现有字段、筛选和嵌图能力；
- 图片墙 Sheet 改名、新增双分类视图及品牌一级分组。

不重新采集 RPA 数据、不重新调用图片理解或批次分类模型、不修改第四部分 HTML 的分类切换逻辑，也不修改第一、二、三、五部分。

## 导出架构

### 报告生成与 Excel 导出解耦

`render_report()` 继续复制可用高光帧到 `final-report/assets/highlight-frames/`，并输出 `presentation-report.json`、`final-report-data.json`、HTML、Markdown 和 ZIP；但不得调用 `export_highlight_workbook()`，不得写入 `highlight-frames.xlsx`，HTML 也不得生成指向报告目录内 XLSX 的失效下载链接。

新增 `rpa_connector.py export-highlight-workbook` 子命令。它显式接收：

- `--fact-pack-json`：生成该报告的事实包；
- `--presentation-json`：同一报告目录的 `presentation-report.json`；
- `--asset-root`：高光帧图片资源的根目录；
- `--output`：调用方指定的独立 `.xlsx` 路径。

命令只读取这些已存在的确定性产物，调用 `export_highlight_workbook()` 后输出实际文件路径；输入缺失、双分类不可用或图片缺失时遵循既有安全降级规则。导出文件必须位于 `final-report` 目录及其 ZIP 之外，推荐同批次根目录下的独立 `exports/` 子目录。这样离线报告包不会膨胀，仍可通过现有 CLI/任务流按需取得同版本导出文件。

### 数据来源与一致性

导出行继续只包含 `available == true` 的高光帧。标准分类从 `presentation.chapters.chapter04` 的 `standard` 模式读取；本批次标准从同一位置的 `batch` 模式读取。两套分类均映射回同一个 `frame_ref` 和图片路径，不复制图片、不重新分类。

导出器应建立按 `frame_ref` 索引的两份分类映射：

- `standard_category_by_ref`：固定的“人像画面 / 产品画面 / 其他画面”；
- `batch_category_by_ref`：当前批次动态类别标签。

品牌沿用事实包的标题品牌识别规则。多品牌素材以既有“、”连接方式显示；未匹配素材标为“其他品牌”。排序固定为品牌、分类、素材排名、帧秒数/峰值顺序，确保同一输入可复现。

## 工作簿设计

### 高光帧资产

保持现有 `高光帧资产` Sheet：业务字段、表头筛选、冻结行、图片嵌入和等比缩放均保留。其“视觉类型”列继续表示标准分类；为消除双分类歧义，新增“本批次标准分类”列。批次分类不可用时该列显示“本批次标准不可用”，而不是伪造固定分类。

### 标准分类图片墙

原 `高光帧图片墙` 更名为 `标准分类`。它只承载高光帧图片和对应的素材 ID：

- 一级分区：品牌；
- 二级分区：人像画面、产品画面、其他画面；
- 每张图片下方仅显示 `素材 ID`，删除视频/素材标题、排名、点击指数和其他业务指标；
- 图片继续按原始宽高比缩放，按四列画廊排布。

Sheet 顶部设置品牌级内部跳转入口；每个品牌分区内顺序展示其二级分类。无帧的二级分类不渲染空画廊；某品牌没有可用帧时不建立该品牌分区。

### 本批次标准图片墙

新增同级 `本批次标准` Sheet，布局、图片尺寸、素材 ID 标识、品牌一级分组和内部跳转行为与 `标准分类` 一致。其二级分区来自本批次动态分类标签，并以 Presentation 给出的分类顺序展示。

当本批次分类不可用、没有有效分组或映射不能覆盖全部可用帧时，该 Sheet 仍创建，显示明确的不可用原因；不得静默回退为标准分类，也不得混入未分类图片。

## UI 与兼容性

第四部分报告头部不再显示一个必然失效的静态 XLSX 链接。导出能力由新的独立 CLI/任务流提供，调用者可将命令输出以其运行环境支持的下载方式交给用户。已生成的历史报告不做回写；新报告只适用新契约。

`export_highlight_workbook()` 保持可被其他 Python 调用方直接使用；新增参数应向后兼容，允许调用方只传事实包与标准分类 Presentation 并得到可读工作簿。只有明确提供双分类 Presentation 时，才生成完整的“本批次标准”结果。

## 错误处理

- 无可用高光帧：CLI 返回非零并说明未找到可导出的高光帧，不创建空工作簿。
- 指定 JSON 不可读或 JSON 结构不匹配：CLI 返回非零并说明具体输入。
- 图片资源缺失：明细与图片墙跳过无法嵌入的图片并写诊断日志；仍保留其他有效帧。
- 本批次分类不可用：`标准分类` 与明细 Sheet 正常导出，`本批次标准` Sheet 展示不可用状态与原因。
- 输出路径已存在：仅在调用方明确提供该路径时覆盖；不影响任何 `final-report` 内容。

## 验收标准

- 调用 `render-report` 后，`final-report/` 和同级 ZIP 均不存在 `highlight-frames.xlsx`，HTML 不含报告内 XLSX 下载链接。
- 使用同一批事实包、Presentation 与图片资产调用独立导出命令，可生成可打开的 XLSX，且不改变报告目录内容。
- 工作簿 Sheet 顺序为 `高光帧资产`、`标准分类`、`本批次标准`。
- 两张图片墙均按品牌一级、画面分类二级组织；图片下方只出现素材 ID，不出现素材/视频标题。
- `标准分类` 覆盖每个可用帧且使用固定三类；`本批次标准` 使用动态类别和其原始顺序，或明确显示不可用原因。
- 两张图片墙与明细 Sheet 的图片数量、素材 ID 和可用帧集合可与事实包逐一核对；现有报告渲染和双分类前端测试不回归。
