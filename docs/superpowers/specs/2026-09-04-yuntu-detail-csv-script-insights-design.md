# 云图详情 CSV 兼容与第三章脚本洞察设计

## 1. 背景与目标

当前技能已经具备 CSV 读取和嵌套 JSON/Python 字面量解析能力，但 `normalize_detail_records()` 只消费旧版详情对象中的顶层 `trends`、`scriptText` 和 `contentFormula` 字段。现有落盘详情 CSV 使用 `coreData.*`、`secondTrend.*`、`contentFormula.*` 和 `creativeBreakdown.*` 的扁平点号字段，导致 CSV 虽然解析成功，脚本、内容公式和秒级趋势却无法进入规范化结果。

本设计不新增独立 CSV 导入脚本，也不接入新的连接器。目标是：

1. 让现有规范化器同时兼容旧版详情响应和当前扁平详情 CSV。
2. 将脚本文本、内容公式和创意拆解沉淀为第三章可审计事实。
3. 在不伪造脚本时间戳、不越界外推 TOP1000 的前提下，补齐 `03｜脚本洞察`。
4. 让第五章“脚本分析”Tab 与第三章复用同一份规范化事实。
5. 未来切换到 `rpa.conn.juliang.yt.industry.content.rankings.details` 时，只替换连接器入口或输入结构，不改变后续分析和渲染契约。

## 2. 数据事实与范围

当前 6 份样本文件包含 5 个唯一素材，其中 `7659409261740343346` 重复出现两次。详情文件提供完整核心指标、部分内容公式、部分脚本文本和五类秒级趋势，但不提供行业榜单列表、上一周期、全行业基准或高光图片资产。

因此第三章的默认分析范围定义为 `selected_detail_materials`（已获取详情素材），而不是行业 TOP1000。脚本正文、内容公式和创意拆解的缺失必须逐字段记录；当前 CSV 没有 `scriptSegments`，所以不生成帧-话术或秒点-话术对应关系。

## 3. 方案与边界

### 3.1 输入解析与规范化

保留现有链路：

```text
parse_csv_records()
  → normalize_detail_records()
  → report-data / analysis-units
  → 单次 AI 分析
  → presentation
  → final-report.html
```

`parse_csv_records()` 继续负责 CSV 分隔符、编码、嵌套 JSON 和安全字面量解析。`normalize_detail_records()` 增加扁平结构识别：

- `dateType`、`customStartDate`、`customEndDate` → `date_range`
- `videoUrl` → `video_url`
- `secondTrend.<指标>.*` → `trend_series`、`high_points`、`loss_points`
- `contentFormula.*` → `content_formula`
- `creativeBreakdown.*` → `creative_breakdown`
- `contentFormula.视频脚本.text` → `script_text`

旧版顶层字段仍走原有路径。两种路径输出同一规范化契约，不能通过修改连接器返回结果来适配。

### 3.2 去重与来源

素材主键使用 `material_id`。同一素材重复出现时，核心指标、标题、趋势和脚本内容必须一致；不同视频 URL 作为 `video_url_variants` 保留，不能因 URL 差异生成两条素材结论。原始 CSV 路径和文件哈希进入来源信息，原始文本不可覆盖。

### 3.3 第三章脚本事实包

新增 `analysis-units/script-input.json`，但它是章节事实包，不是新的 CSV 转换层。事实包包含：

- 章节范围和素材覆盖数；
- 每个素材的 `material_id`、脚本文本、内容公式、创意拆解和字段可用性；
- 公式标签、商品卖点、使用场景、营销活动和呈现形式的确定性频次；
- 可引用的核心指标和来源路径；
- 脚本时间戳可用性，当前明确为不可用。

事实层只做整理、去重和统计，不生成“有效”“导致”“提升”等业务判断，也不从标题、趋势或画面反推脚本。

### 3.4 AI 输出

在现有单次模型调用中加入脚本事实包，新增 `scriptInsights`。每个洞察必须包含 `title`、`summary`、`evidence` 和 `material_ids`，并围绕以下维度形成自然段：

- 开场钩子和问题引入；
- 信任、证明和品质表达；
- 卖点、场景、促销和行动召唤组合；
- 可复用结构与需要品牌化改写的部分；
- 下一轮可验证的脚本变量和指标。

模型不得把详情素材样本概括成行业普遍规律，不得把内容公式标签当成因果证据，不得把 `convertCnt` 解释为订单数，不得声称某句脚本导致某个秒级指标变化。脚本缺失时只输出数据不足状态。

### 3.5 报告展示

03 章由事实统计和已校验的 `scriptInsights` 组成，明确显示“已获取详情素材”范围、脚本覆盖数和缺失状态。第五章脚本 Tab 展示原始脚本、内容公式和创意拆解；没有脚本时间戳时显示不可用说明，不展示帧-话术关联。

## 4. 错误与降级

- CSV 表头或行结构非法：沿用现有解析失败行为。
- 扁平趋势字段缺失：只将对应指标标记为不可用，不补造趋势点。
- 脚本或公式缺失：保留素材记录，字段级标记 `source_empty`。
- 重复素材指标冲突：停止该素材规范化并报告冲突，不静默覆盖。
- 无榜单列表：允许生成详情范围的 03/05 事实，但禁止生成榜单、环比和行业基准结论。
- 无高光图片：第五章继续按现有高光资产不可用规则渲染，不生成视觉结论。

## 5. 验收标准

1. 旧版详情对象和当前扁平详情 CSV 均能生成同构规范化详情记录。
2. 当前 6 份样本被识别为 5 个唯一素材，重复素材不会重复进入 AI 证据。
3. 五类秒级趋势、脚本文本、内容公式和创意拆解按字段正确进入事实包。
4. 第三章能在脚本覆盖不足时展示真实覆盖率和缺失状态。
5. AI 输出不包含帧-话术推断、因果表述或无证据行业外推。
6. 第五章脚本 Tab 与第三章使用同一规范化事实，旧批次无脚本数据时继续兼容原占位状态。
7. 全量单元测试、编译检查和差异检查通过。
