# 云图第三章脚本洞察前端样式重构设计方案

## 1. 背景与问题

上一轮已在 `codex/yuntu-detail-script-insights` 完成第三章的初步数据投影和交互，但当前页面把“脚本文案覆盖率、关键词、卖点、公式图表、AI 洞察、素材明细”堆叠在一个大容器中，层级不清、卡片视觉不统一、AI 结论不突出，且与千川已上线报告的阅读节奏不一致。用户需要的是一份可直接阅读的批量脚本诊断，而不是内部字段的逐项罗列。

本轮只重构第三章的前端信息架构、HTML 结构、JavaScript 交互和 CSS 视觉，不重新设计云图事实包和提示词，不接入新的 RPA 连接器，也不新建 CSV 导入适配层。千川参考基线为：

## 2. 目标行为

当 `chapter03.scriptDashboard` 存在时，第三章按以下固定顺序渲染：

1. **AI 二次分析区**：两张同级结论卡，分别展示“一二级内容公式”和“脚本文案”。两张卡都采用标题、完整结论、证据引用的统一结构，不把脚本/公式事实重复成第三类 AI 卡片。
2. **关键词洞察区**：一个三列横向面板，左列“一句话结论”、中列“高频关键词云”、右列“从关键词云提炼的卖点”。桌面端左中右等高对齐，移动端按左→中→右纵向堆叠。
3. **内容公式汇总数据区**：完整宽度的一级标签柱状图；点选一级标签后进入二级标签分布，显示当前一级标签、计数、二级柱状/列表和“返回一级标签总览”。
4. **范围提示/数据边界**：只保留简短的“已获取详情素材”范围和缺失提示；不在第三章重复渲染单素材脚本文案、创意拆解或复制按钮，这些事实属于第五章。

当 AI 不可用时，确定性关键词和公式图表仍需正常展示；当公式或关键词为空时，在对应列显示明确空状态。

## 3. 事实与 AI 边界

- 前端只消费现有 `chapter03.scriptDashboard`：`insights`、`conclusion`、`keywords`、`sellingPoints`、`dimensions.contentFormula`、`coverage`。
- `insights` 固定为两维：第一条分析一/二级内容公式，第二条分析脚本文案。前端不按标题、画面文本或其他章节事实拼接新的分析。
- 关键词的字号、顺序和计数使用确定性 `keywords[*].count`；AI 只提供已经投影过的结论和卖点，不修改频次。
- 标题与视频画面原文不进入 AI 二次分析，但规范化后的内容公式标签已经进入 `dimensions.contentFormula`，图表必须照常统计。
- 不显示帧—话术、秒点—话术对应，不将脚本结论解释为导致点击、转化或完播的因果。

### 4.1 AI 卡片

AI 区使用千川的 `insight-stack`/`insight-row` 信息密度，但改为云图暖色卡片：顶部显示维度徽标，标题最多两行，正文保持 1.75 行高，证据只作为低对比度尾注。两张卡在 960px 以上并排，在窄屏单列；不再把 `material_ids` 作为醒目的正文标题。

### 4.2 左中右关键词面板

使用三个同高 `article`：

- 左列：一句话结论用较大字号突出，摘要作为补充，不显示“暂无分析”以外的模板化长句。
- 中列：关键词按确定性频次降序，最多显示 24 个；字号范围固定在 `0.95rem–2.3rem`，颜色仅用于层次，不单独承载频次。
- 右列：最多四张卖点小卡，每张显示标题和一段描述；没有卖点时保留空状态高度，避免左右跳动。

### 4.3 公式图表与钻取

一级图表复用千川 `renderColumnChart` 的视觉语言：基准线、网格线、柱顶计数、标签和点击提示。当前实现已经使用 `data-script-formula`；本轮只统一柱宽、间距、坐标区高度、按钮焦点和钻取过渡，不改变 `primary`/`secondary` 数据含义。

钻取视图必须：

- 标题明确为“一级标签：{label}”；
- 展示该一级标签的总计数和二级标签计数；
- 只显示当前一级标签的二级数据；
- 提供可聚焦的“返回一级标签总览”按钮，返回后焦点回到原一级柱；
- 尊重 `prefers-reduced-motion`，无障碍名称包含标签和动作。

## 5. 模块边界与实现策略

| 文件 | 本轮职责 |
|---|---|
| `scripts/yuntu_report_sections.py` | 只输出第三章批量展示骨架、AI 卡片、三列关键词面板和公式 dashboard 数据属性；移除第三章重复的素材明细展示 |
| `scripts/templates/final-report-template.html` | 保留现有报告外壳，重写第三章公式看板 DOM 生成、钻取过渡、焦点恢复和空状态 |
| `assets/report/unified-report.css` | 新增/收敛 `.unified-yuntu` 下第三章专属 token、卡片、三列网格、柱状图、钻取和响应式规则 |
| `tests/test_yuntu_report.py` | 验证 HTML 顺序、第三章 mount 点、无重复第五章字段和关键 class/data 属性 |
| `tests/test_yuntu_presentation.py` | 验证既有 `scriptDashboard` 投影不被样式改动破坏 |

`scripts/yuntu_analysis.py`、`prompts/yuntu-analysis-prompt.md` 和 CSV 解析链路本轮不修改；如测试发现字段缺失，只允许补充前端兼容读取，不改变事实源。

## 6. 视觉与响应式规范

- 沿用 `unified-report.css` 的云图暖棕色 token、细边框和轻阴影，避免新增第三套颜色系统。
- AI 卡片、关键词三列、公式图表均使用 8px 圆角和一致的内边距；标题层级只使用 `h3/h4` 两级。
- 桌面断点：`min-width: 960px` 为 AI 双列和关键词三列；`760–959px` 关键词改为两列，卖点占满下一行；`max-width: 759px` 全部单列。
- 公式图表在窄屏允许横向滚动，单柱最小宽度 76px，标签不截断；钻取布局在窄屏改为上下结构。
- 所有按钮具备 `:focus-visible`，颜色对比度满足正文可读性；动画只用于进入/离开状态，关闭动画时仍保持内容顺序。

## 7. 非目标、异常与回滚

- 不改变 AI 输出 schema、事实包字段、连接器调用、第五章秒级拆解和第四章高光画面。
- AI 缺失：显示“暂无脚本洞察”，但关键词和图表照常显示。
- 关键词/卖点缺失：对应列显示“暂无可用关键词/卖点，数据不足以判断”，不压缩其他列。
- 公式为空或二级为空：图表显示空状态或“该一级标签暂无二级标签”，不伪造柱形。
- 若模板 JS 异常，服务器输出的 AI 文本、关键词和一级公式骨架仍可读；只牺牲动态钻取。

- [ ] 桌面端关键词洞察为左/中/右三列等高面板，移动端按相同语义顺序单列，不出现横向裁切。
- [ ] AI 区明确区分“一二级内容公式”和“脚本文案”，没有把标题或画面原文作为 AI 结论维度。
- [ ] 一级柱状图可点击进入对应二级标签，返回按钮可用且焦点可恢复；键盘 Enter/Space 与 reduced-motion 均可用。
- [ ] 第三章不再重复展示第五章的单素材脚本文案、创意拆解和复制动作。
- [ ] 无 AI、无关键词、无公式三种空状态均可读，且不影响其他章节。
