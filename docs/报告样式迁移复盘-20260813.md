# 云图报告样式迁移复盘

日期：2026-08-13  
范围：云图报告 `02｜人群洞察`、`04｜高光画面洞察` 与千川参考报告的样式复刻

## 一、结论摘要

本次修改没有稳定完成“只迁移样式、不改变云图数据与交互契约”的目标。主要原因不是数据源不同，而是两个报告确实由独立的生成器、内联脚本和样式体系生成；在没有先完成组件结构对齐和事件边界梳理的情况下，直接在统一 CSS/JS 层叠加参考样式，造成了以下问题：

- 参考报告的视觉层级没有被完整迁移，部分目标元素仍受原组件样式覆盖。
- 高光分页存在两套实现同时处理同一批 DOM，导致翻页行为不稳定或失效。
- 高光卡片结构被改动时，没有同步验证标题跳转、分页和大图查看三个交互。
- 通过 CSS 覆盖解决局部视觉问题，但没有建立“参考 DOM 结构 -> 云图 DOM 结构”的明确映射。
- 生成后的 HTML、内联脚本和浏览器实际行为之间缺少完整的端到端验收。

当前代码已被用户回退，报告重新生成后恢复为回退版本的结构，例如高光卡片仍使用 `highlight-source-link`，统一脚本仍包含 `normalizeYuntuHighlightPagination`。本复盘不改变当前代码状态。

## 二、目标与实际结果

### 原始目标

以千川报告为视觉参考，调整云图报告中的：

1. `02｜人群洞察` 八大人群分布与钻取区域。
2. `04｜高光画面洞察` 的分类切换、洞察区、高光帧卡片和分页区域。

数据继续使用云图已有数据源，不要求重新设计方案，不要求改变业务口径。

### 用户反馈暴露的问题

- “返回八大人群分布”按钮样式与千川报告不一致。
- 人群钻取卡片下方留白过多。
- 高光帧底部“查看素材”不符合参考报告，标题应承担跳转功能。
- 高光帧缺少白色卡片兜底，标题位置不符合参考样式。
- 人群汇总展开按钮外圈底色与下方数据区不一致。
- 高光画面分类选中时缺少深棕色标识。
- 高光区域翻页功能失效。

这些反馈说明问题同时存在于视觉层、结构层和交互层，不能只靠增加 CSS 规则解决。

## 三、根因分析

### 1. 把“样式复刻”处理成了 CSS 覆盖任务

参考报告不是一个可直接套用的主题文件。两份报告的类名虽然有重合，例如 `.highlight-dashboard-tabs`、`.highlight-frame-card`、`.collapsible-toggle`，但它们的父级结构、默认样式、脚本初始化方式和状态字段并不完全相同。

因此，同名选择器并不代表同一组件。仅增加 `.unified-yuntu ...` 规则，无法保证布局、状态和交互都与参考报告一致。

### 2. 没有先做组件契约对照

在实施前应逐项确认：

- 参考组件的 DOM 层级。
- 云图组件的 DOM 层级。
- 哪些节点是视觉容器，哪些节点是交互控制器。
- 哪个脚本负责初始化、分页、切换和跳转。
- 状态是通过 `aria-selected`、`hidden`、`data-*` 还是静态 radio 控制。

本次过程中先改了生成器和 CSS，之后才发现云图内联脚本与统一脚本都在处理高光分页。这使得后续修复变成了对冲突的补丁，而不是一次清晰的迁移。

### 3. 高光分页出现重复控制器

目标 HTML 中同时存在：

- 生成器内联脚本中的 `paginateHighlightPanel`。
- 统一脚本中的 `normalizeYuntuHighlightPagination`。

两者都查询 `[data-highlight-frame-card]`、`[data-highlight-pagination]` 和 `[data-highlight-page]`，但使用了不同的页码属性：

- `data-highlight-current-page`
- `data-unified-highlight-page`

这会导致初始化顺序和事件捕获顺序决定最终状态。该问题属于架构级事件冲突，不能通过按钮颜色或 `z-index` 修复。

### 4. 生成器修改与已生成 HTML 的验证脱节

高光卡片由 `scripts/yuntu_report.py` 生成，CSS/JS 又会被内联到最终 HTML。期间曾出现“源代码已修改，但浏览器仍看到旧结构”或“重新生成后回到旧结构”的情况，说明验证时没有始终明确区分：

- 当前源代码。
- 当前生成输入。
- 当前最终 HTML。
- 当前浏览器加载的文件。

报告类任务必须把这四层作为一条可追踪链路。

### 5. 测试覆盖偏向字符串存在性，缺少真实交互验收

已有测试可以验证某个 class 或 CSS 字符串存在，但这不足以证明：

- 分类切换能正常显示对应 panel。
- 下一页按钮确实改变可见卡片。
- 标题跳转确实激活目标单素材。
- 折叠按钮的视觉外圈与内容区颜色一致。
- 参考样式没有被后续规则覆盖。

本次问题主要发生在 DOM 事件和最终渲染层，而不是 Python 语法或字符串拼接层。

## 四、过程中的判断失误

1. **过早修改实现**：没有先完整读取千川报告的相关 DOM、CSS 和脚本，就开始在云图层叠加样式。
2. **把相似类名当作共享组件**：忽略了两个报告虽有相同命名，但实际由不同代码路径维护。
3. **重复实现交互**：为了“统一体验”增加第二套分页，而不是复用目标报告已有分页逻辑。
4. **缺少单一所有者原则**：没有明确规定分页、分类切换和素材跳转各自只能由一个脚本负责。
5. **依赖局部浏览器截图**：看到某个按钮或卡片不一致时，直接针对局部增加规则，未先检查整段组件的布局和事件链。
6. **没有在每次重新生成后清理旧假设**：源代码回退或重新渲染后，仍沿用前一次修改的验证结论。

## 五、影响范围

### 用户可见影响

- 02 区域的折叠按钮与数据卡底色不协调。
- 人群钻取状态下出现额外留白，信息密度与参考报告不一致。
- 04 区域分类选中态不明显。
- 高光帧标题、指标和跳转入口层级不一致。
- 分页点击后页面状态可能不变化，或显示页码与实际卡片不一致。

### 技术影响

- 统一报告脚本承担了超出其职责范围的云图组件控制。
- CSS 覆盖层逐渐变成高优先级补丁集合，增加后续维护风险。
- 生成器、模板、内联脚本和资产复制之间的依赖关系不够清晰。

## 六、正确的后续实施方案

### 阶段 1：冻结现状

在任何修改前固定一份基线：

- 当前 Git commit。
- 当前输入 JSON 和事实包路径。
- 当前最终 HTML 的 hash 和生成时间。
- 02、04 区域的桌面和移动截图。
- 当前分页、分类切换、素材跳转的行为记录。

### 阶段 2：建立组件映射表

为每个组件记录以下字段：

| 组件 | 参考报告结构 | 云图结构 | 复用方式 | 唯一交互所有者 |
| --- | --- | --- | --- | --- |
| 人群汇总折叠 | 参考 DOM | 云图 DOM | 保留云图结构，仅迁移视觉属性 | 云图内联脚本 |
| 八大人群分布 | 参考卡片/图表布局 | 云图图表 DOM | CSS 适配，不改数据计算 | 云图 audience 脚本 |
| 高光分类 | tablist + tabpanel | tablist + tabpanel | 对齐状态属性和容器结构 | 云图高光脚本 |
| 高光分页 | pagination + cards | pagination + cards | 只保留一套实现 | 云图高光脚本 |
| 素材跳转 | 标题或来源入口 | `data-jump-material` | 统一入口位置，不重复绑定 | 单素材脚本 |

### 阶段 3：先做结构，再做样式

如果参考报告需要标题位于图片下方、白色卡片兜底等结构变化，应先修改生成器输出的 DOM，再写 CSS。不要用 `order`、负 margin 或高度补丁模拟结构变化。

### 阶段 4：明确脚本边界

统一报告脚本只处理真正跨报告的能力，例如导航、高光灯箱或无组件依赖的通用增强。云图已有的分类、分页、钻取和素材跳转逻辑必须由云图脚本单独负责，禁止统一脚本再次注册同类事件。

### 阶段 5：建立行为测试

至少覆盖以下真实行为：

- 点击“展开人群汇总数据”后 body 显示，按钮文案切换。
- 点击八大人群柱体后进入钻取，返回按钮恢复总览。
- 点击高光分类后 panel 切换，旧 panel 隐藏。
- 点击下一页后第一页卡片隐藏、第二页卡片显示、页码更新。
- 点击素材标题后单素材 tab 激活并滚动到深度分析。

### 阶段 6：最终验收

每次生成后必须验证：

1. 源代码与最终 HTML 的 class、脚本版本一致。
2. 目标 HTML 只包含一套分页初始化逻辑。
3. 桌面端和移动端没有横向溢出或异常空白。
4. 用户反馈中的每个节点都有对应的 DOM/CSS/行为证据。
5. 全量测试、语法检查、生成命令和浏览器交互检查均通过。

## 七、当前状态

- 代码已按用户操作回退，本复盘没有修改现有实现。
- 报告已基于回退后的代码重新生成。
- 当前生成结果仍包含回退版本的 `highlight-source-link` 和统一分页函数，这是当前代码状态的真实反映，不应误认为迁移修复已经保留。
- 后续若重新实施，应从“组件映射 + 单一交互所有者 + 基线截图”开始，而不是继续叠加 CSS 补丁。
